# Дело Ритма — облачная версия

Новая самостоятельная версия платформы: публичный сайт лагеря, запись детей, кабинет организатора, PostgreSQL, экспорт списка участников в Excel и документа на трансфер в Word.

**Apps Script и Google Таблицы не нужны для работы новой версии.** Исторические данные переносятся один раз через экспорт Google Таблицы в XLSX и импорт из кабинета. Старую таблицу можно оставить как архив до завершения проверки миграции.

## Архитектура

- Node.js 22+ / Express — API и веб-приложение.
- PostgreSQL — смены, заявки, дети, статусы, документы, лист ожидания, журнал действий.
- `web/` — публичный сайт и административная панель.
- ExcelJS — XLSX с участниками по смене.
- docx — DOCX-шаблон списка на трансфер.
- Свидетельства хранятся в PostgreSQL как приватные файлы и доступны только авторизованному администратору.

## Локальный запуск

1. Установите Node.js 22 или новее и PostgreSQL 16+.
2. Создайте базу `delo_ritma`.
3. Скопируйте `.env.example` в `.env`, укажите `DATABASE_URL`, `ADMIN_EMAIL` и уникальный пароль длиной не менее 12 символов.
4. Установите зависимости и запустите сервер:

```bash
npm install
npm run check
npm start
```

Откройте `http://localhost:3000`, кабинет администратора — `http://localhost:3000/admin`.

При первом запуске приложение автоматически создаёт таблицы и начального администратора. Повторный запуск не перезаписывает пароль существующего аккаунта.

## Render

В корне находится `render.yaml`. Blueprint описывает:
- Node web service в Frankfurt на плане Starter;
- PostgreSQL в Frankfurt на плане Basic-256mb;
- внутреннее подключение сервиса к базе через `DATABASE_URL`;
- ручной ввод секретов `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `TG_BOT_TOKEN`, `TG_CHAT_ID`.

Ориентир по прайсу Render на ноябрь 2026: веб-сервис $7/мес. + PostgreSQL $6/мес. = около $13/мес., до дополнительного трафика и роста хранилища. Бесплатная БД не используется для постоянных данных. Перед созданием ресурсов проверьте итоговую сумму в Render Blueprint plan. Не подтверждайте Sync, пока не проверили план и секреты.

## Перенос старых данных

1. В Google Таблице выберите **Файл → Скачать → Microsoft Excel (.xlsx)**.
2. Войдите в новый кабинет администратора и откройте **Перенос данных**.
3. Загрузите XLSX. Импортирует листы `Смены` и `Заявки`, старается сохранить ID и номера старых заявок. Повторный импорт не создаёт повторные заявки с тем же старым номером.
4. Сверьте количество смен, участников и статусы со старой таблицей.
5. Проверьте карточку участника, приватные документы, Excel-экспорт и документ на трансфер.
6. Сделайте тестовую заявку, затем отмените тестовую запись.
7. Только после сверки переключайте домен/ссылку на новую версию. Старая Google Таблица остаётся архивом, пока миграция не подтверждена.

## Экспорт

- **Excel участников** — один файл на выбранную смену, с контактами родителей, тренером, направлением, аллергиями, ограничениями, трансфером, статусом и датой заявки.
- **Word на трансфер** — готовая таблица участников, отметки посадки туда/обратно, поля маршрута, времени отправления и ответственных.

## API

Публичные:
- `GET /api/public/shifts`
- `POST /api/public/bookings`
- `POST /api/public/waitlist`

Администраторские (требуют HttpOnly session cookie):
- `POST /api/admin/login`
- `POST /api/admin/logout`
- `GET /api/admin/me`
- `GET /api/admin/dashboard`
- `GET/POST /api/admin/shifts`
- `PATCH/DELETE /api/admin/shifts/:id`
- `GET /api/admin/bookings`
- `PATCH /api/admin/bookings/:id/status`
- `GET /api/admin/exports/shifts/:id/participants.xlsx`
- `GET /api/admin/exports/shifts/:id/transfer.docx`
- `POST /api/admin/import/legacy-xlsx`

## Важные эксплуатационные заметки

- Не коммитьте `.env`, пароли и токены.
- В production используйте HTTPS. Сессионная cookie имеет HttpOnly, Secure и SameSite=Strict.
- Ограничение публичных заявок защищает от простого спама.
- Перед открытием реального набора заполните и опубликуйте юридически корректную политику обработки персональных данных и согласие, проверьте резервное копирование базы и срок хранения данных детей.
- Перед запуском нужно провести реальную проверку всех сценариев и восстановление базы из резервной копии.
